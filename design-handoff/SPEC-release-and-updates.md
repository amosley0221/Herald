# Herald — releases, release notes, and no-reinstall updates

Two hard requirements from the owner:

1. **Every Android change ships with a release-notes page**, viewable in the app and on the web.
2. **Both apps update themselves** — the user never manually installs a new build after the first one.

## Versioning

Semantic versioning `MAJOR.MINOR.PATCH`, shared across Android and desktop (one tag per release, e.g. `v1.4.2`). Android `versionCode` = monotonically increasing integer derived from the tag.

## Release notes — single source of truth

- `CHANGELOG.md` at repo root, Keep-a-Changelog format. Every PR that touches user-facing behavior adds a line under `## [Unreleased]` with a section: Added / Changed / Fixed / Removed.
- CI refuses to merge a PR that changes `apps/android/**` or `packages/core/**` without a CHANGELOG entry (simple grep in a GitHub Action).
- On tag, CI cuts `## [Unreleased]` into `## [x.y.z] — YYYY-MM-DD`, and:
  - publishes it as the **GitHub Release body**,
  - writes `releases/x.y.z.json` `{version, date, notes_markdown, android_version_code, min_supported}` and regenerates `releases/index.json`,
  - deploys the `releases/` folder to GitHub Pages → public **release notes page** at `https://<user>.github.io/herald/releases/`.
- **In-app "What's new" screen** (Preferences → About → What's new): fetches `releases/index.json`, renders in Herald style — version in Cinzel, date as roman numerals, notes in Jost 300, hairline between versions. After an update lands, show a one-time toast "Updated to 1.4.2 · What's new" that opens this screen.

## Android — update without reinstalling

Two layers, both required:

**A. Over-the-air code push (Dart/JS changes — the vast majority).**
- Flutter → **Shorebird** (`shorebird release android` / `shorebird patch android`). Patches download silently on launch and apply on next start. Free tier is sufficient for one user.
- React Native/Expo → **Expo Updates / EAS Update**, same behavior.
- Patches carry the same version + a patch number; the What's new screen must list patches too.

**B. Native binary updates (rare — new permissions, SDK bumps).**
- Distribute the APK from GitHub Releases. Build in an **in-app updater**: on launch, GET `releases/index.json`; if `android_version_code` > installed, show a hairline banner "Version 1.5.0 is available · Install" on Today. Tapping downloads the APK and hands it to the system package installer (`REQUEST_INSTALL_PACKAGES` permission; user taps once to confirm — Android does not permit fully silent installs for sideloaded apps). No Play Store account or manual file transfer needed.
- Alternative if the owner prefers zero prompts: publish to Play Store internal testing; Play auto-updates. This adds a $25 developer account.

Sign both channels with the same keystore; store it in CI secrets.

## Desktop — update without reinstalling

- **Flutter desktop**: `auto_updater` package (Sparkle on macOS, WinSparkle on Windows) pointing at an `appcast.xml` generated by CI alongside `releases/index.json`. Checks on launch, downloads in background, installs on next quit.
- **Tauri**: built-in updater plugin with the same GitHub Releases feed; sign updates with the Tauri key.
- macOS builds must be notarized or the updater will be blocked by Gatekeeper; Windows builds should be Authenticode-signed (a self-signed cert is acceptable for a single-user app; the first install will warn once).

## CI (GitHub Actions) outline

```
on: push tags v*
jobs:
  changelog  → cut Unreleased, emit releases/x.y.z.json, index.json, appcast.xml
  android    → shorebird release (or expo publish) + build signed APK → upload to Release
  windows    → build, sign, upload installer + updater manifest
  macos      → build, sign, notarize, upload .dmg + appcast
  pages      → deploy releases/ to GitHub Pages
on: pull_request
  guard      → fail if apps/android or packages/core changed without a CHANGELOG diff
```

## Definition of done for any change

1. Code + CHANGELOG entry in one PR.
2. Tag → CI publishes release notes page, Android patch/APK, desktop updaters.
3. Open the app on both platforms: update arrives without visiting a store or copying files; "What's new" shows the entry.
